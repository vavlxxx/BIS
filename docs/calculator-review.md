# Проверка калькуляторов

Эта ветка отделяет проверенные численные расчёты от форм, для которых нет подтверждённой методики. До проверки шести расчётов АВОК профильным инженером её нельзя выпускать на `main`.

## Дымоудаление

Основа: [ГОСТ Р 53300-2009, приложение Б](https://protect.gost.ru/gost/details/8f5e6de8-3d05-45ec-b59a-b4d6f4236678). Расход `La` берётся с характеристики фактически установленного вентилятора при приведённом давлении. Он не выводится из проектного расхода. Для каждого участка нужны геометрия шахты, местное сопротивление, коэффициент трения и паспортное сопротивление закрытого клапана.

В приложенном к задаче ручном расчёте `La = 14 500 м³/ч`, а проектный расход равен `27 500 м³/ч`. Это разные исходные данные. Напечатанное в PDF значение `Psa = 365,52 Па` не следует из напечатанных там же значений `Psv = 250 Па`, `Tпг = 760 К`, `Tв = 619 К`, `Tа = 20 °C`, `h = 11 м` и формулы Б.1. Подстановка по Б.1 даёт около `44,19 Па`. Следовательно, итог PDF не является контрольным числом для кода без уточнения исходных данных или исправления PDF.

## Герметичность

Основа: [ГОСТ 34060-2017, пункты 7.3–7.5](https://protect.gost.ru/gost/details/8629d8cd-4237-4ac6-a30c-d3ebda9445f2). Коэффициенты классов A/B/C/D: `0,097 / 0,032 / 0,011 / 0,004`. Проверка проектного класса и ограничение утечки в `8 %` выполняются отдельно.

При площади `145,925 м²`, давлении `116 Па`, расходе у вентилятора `4111,2 м³/ч`:

| Источник | Расход по решёткам, м³/ч | Утечка, м³/ч | Удельная утечка, м³/(ч·м²) | Класс по величине утечки | Предел класса B |
| --- | ---: | ---: | ---: | --- | --- |
| Таблица XLSX | 4015,2672 | 95,9328 | 0,6574 | B | Соблюдён |
| Отчёт PDF | 3893,688 | 217,512 | 1,4906 | A | Превышен |

Заключение «класс B» в PDF противоречит указанным там же измерениям: предел B при `116 Па` равен `0,7031 м³/(ч·м²)`. В обоих примерах утечка остаётся ниже `8 %` расхода у вентилятора.

## Шесть расчётов АВОК

В репозитории и приложениях нет полного текста методики [АВОК 5.5.1-2023](https://www.abok.ru/news.php?id=6033) или полных ручных контрольных расчётов для этих шести сценариев. Поля из письменных замечаний заказчика добавлены во все шесть форм. Прежний код использовал константы и неполные исходные данные, поэтому его численные результаты и протоколы отключены. В форме явно указан статус проверки. Это не подтверждает совпадение с ручными расчётами заказчика.

Перед выпуском нужно сверить каждую формулу с методикой и профильным инженером, определить дополнительные данные, которые потребуются по формулам сверх уже перечисленных заказчиком, получить независимые контрольные значения для всех шести сценариев и проверить протоколы. Только после этого можно включать их расчёты и выпускать ветку на `main`.
